# Public projection and historical commitments

## Versioned originals

The v1.0 public release derives from the frozen Round 1–7 research archive with SHA-256 `9dcc125122396d50f27129e51e12a4a6fe935526c9dbb13b0869e35c10ad5dfe`. That privately retained original is never overwritten. The published v1.0.0 data ZIP, checksum, tag and historical scientific files remain unchanged.

Round 8 has a separate original registration, source/input commitments, immutable final snapshot and versioned public projection. The prospective 444-window schedule was frozen before formal measurement. Later cleanup and OS resource-envelope observations keep their actual post-registration labels and timestamps; publication does not turn them into preregistration. The locally verified v1.1.0 package and manifest commitments are recorded in DATA.json; asset availability must be checked at the versioned release page. Local preparation does not assert publication or independent download verification. The v1.0 archive hash is not reused as a Round 8 commitment.

## Protected evidence and permitted metadata changes

Scientific inputs, request vectors, tree checkpoints, proof frames, raw measurement/warmup rows, timed-client summaries/completions, CPU-clock receipts, schedules and measured Go/dependency/analyzer source stay byte-identical. Negative outcomes, failures, invalid preflight attempts and slow observations are not removed to improve a result. Optional preflight source001/002 snapshots are exact historical copies and are labelled separately from measured source003.

The registered Windows schedule and Linux runtime schedule retain their distinct CRLF/LF bytes and historical hashes. Their comparison allows only exact CRLF/LF equivalence in memory, with strict JSON and entry order retained. Each public file must still match its own original bytes; no schedule is rewritten or generally reformatted to pass verification.

Publication may project only reviewed private filesystem/account/endpoint identifiers in metadata or documentation. Structured metadata uses finite field selectors rather than unrestricted replacement over every JSON string. Workspace prefixes, complete URLs and complete server authorities use stable placeholders; URL scheme/suffix and ports, command order, PIDs/start ticks, CPU ticks, qdisc settings, timing values, counts, thresholds and outcomes remain unchanged. Controlled test-network addresses remain experimental settings, not private-host redactions.

EVAL contains both scientific data and path-bearing provenance. Its dataset/run paths, input-manifest receipt key and explicitly identified config/environment path fields may be projected, so its public file hash can differ from its historical original hash. Every raw request record, numerical summary/completion value, resource/clock observation, comparison and engineering classification remains unchanged. This is not a claim that all bytes of a path-bearing evaluation JSON file are identical after projection.

The narrow registered archive-check preflight completion exception permits private prefixes in `data_hashes` keys to be projected. It is not a timed-client completion. Its scientific values and original hash binding remain intact. A private identifier in a protected raw record is a failure requiring specific review; the row is neither silently rewritten nor omitted.

RSS snapshots and sampled/high-water memory observations remain recorded as such. Publication does not relabel them exact interval peaks or equate allocation flow with retained memory. Host-specific CPU-clock receipt bytes and their digest references remain unchanged.

## Original/current hashes and independent verification

`PUBLIC_MANIFEST.json` records each included relative path, public and historical original SHA-256, public/original byte lengths, preservation class, exact change flag, and projection categories/counts. Omitted original paths/hashes/lengths and reasons are listed. The manifest's own bytes are bound by the release archive checksum and separately published manifest digest. Actual private replacement tokens and private collection provenance are not public artifacts.

For Round 8, `REGISTRATION.json` remains byte-identical. `REGISTRATION_BINDINGS.json` maps every original committed path to an exact public file, a declared metadata projection or the excluded measured executable. Measured source and analyzer remain exact. A projected controller/config no longer satisfies the original whole-tree registration validator; this is documented rather than hidden by changing the validator or registration.

Historical EVAL source-receipt digest/length values remain historical. The public checker binds them to manifest **original** values, binds recomputed receipts to **current** public values, and compares the scientific evaluation fields. It accounts explicitly for dataset/run metadata paths and the reanalysis runtime annotation. It never silently ignores every field named path, hash or source, and it does not replace historical receipts with current digests to make a check pass.

Version-specific verification uses `tools/verify_public.py` for v1.0 and `tools/verify_round8_public.py` for v1.1. The latter audits all 437 input files and 444 scheduled windows using the unchanged analyzer, including clocks/process identities and unfavorable gate outcomes. Verification is read-only and starts no benchmark. A checksum/inventory proves byte identity to a trusted published checksum; numerical consistency does not constitute a fresh physical replication or authenticate an archive whose trust anchors were also rewritten.

## Exclusions and reuse

Excluded categories include credentials, externally authored paper PDFs/full-text copies, private manuscript/review/delivery products, compiled programs, toolchains, caches and duplicate nested packages. Rebuildable project/dependency source and original dependency notices are provided. Partial full EVAL remains in the original workspace; its public interim REPORT and SHA/byte receipt identify it as incomplete history, not final evidence.

Historical launcher projections document the workflow. They are not turnkey authorization to run an old registered job elsewhere. Any new timing measurement needs a new plan, source/compiler/environment hashes and exclusive run identity. Smoke checks and synthetic unit tests are not empirical performance observations.

The project's MIT grant applies to project-authored code and synthetic data; dependency licenses remain in force. Scientific reuse should cite the repository, actual release version and commit. No manuscript/preprint, journal acceptance or DOI is created by this code/data release.

OpenAI Codex assisted with literature review, study design, code and experimental workflows, analysis, figures and drafting. Human authors remain responsible for verification, interpretation and the final manuscript.
