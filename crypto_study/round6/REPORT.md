# 第三执行环境复现实验报告

日期：2026-10-23。本报告为正式测量完成后的结果文件，不属于预注册文件，也不修改已冻结的协议、代码、原始记录或前两台机器的结果。

第三台机器完成了全部 36,288 条观测。H-locality 与 H-lifecycle 均通过，256 个替代方案条件仍无一通过联合字节／时间门槛。第三台机器与前一台 Linux 服务器的门槛判定一致，但 576 个对应 cell/mode 中，574 个绝对总时间中位数更高。这个结果扩展了已观察的执行环境，不能据此归因于 CPU、负载、分配器或 NUMA 中的任何单一因素。

## 实验与证据完整性

实验仍使用 seed 3407、原有 `r4/dev/3407` 与 `r4/confirm/3407` 字符串、64 个含 domain 的 cell、192 个 bundle、9 个模式、每模式每 bundle 2 次预热与 21 次正式重复。正式运行位于 `../round5/runs/linux_host3_001`，使用冻结的 Round5 Linux 可执行文件，GOMAXPROCS=8。21 项冻结 Go 测试与 39 项冻结 Python 测试在第三主机通过，完整 corpus 预检包含在其中。没有新增进程池或更改门槛。

两台 Linux 机器的运行源码快照分别有 84/84 个文件匹配同一冻结注册。runner SHA256 均为 `89738eddc911ddffd16d739276c5488398fbb010c33ba393b29f0e9c4652ae8e`。Windows 保留其原有 QPC 计时；两台 Linux 使用相同二进制内的 `Go monotonic time.Since`。1,000,000,000 表示纳秒单位换算，不表示实际具有一纳秒有效分辨率。

第三台机器分别与 Windows、前一台 Linux 的全部 1,542 个 corpus 文件逐项一致，36,288 条观测的完整工作身份与执行顺序也一致。1,542 个文件包括 4 个树检查点、192 个 bundle、1,152 个唯一 frame、192 份 bundle 诊断、汇总诊断及顺序文件。相同字节是相同输入下的确定性复核，不增加独立查询样本。

服务器审计与接收后的本地独立审计均通过：验证了 84 个注册文件、1,637 个运行归档文件、4 棵树、192 个 bundle、1,152 个 frame、36,288 条观测、48,672 次证明实例验证及同数量的错误根拒绝，并重现全部评价字段。48,672 是六种格式下 8,112 次查询出现的验证次数，不是独立查询数。Reset frame 未另行存档，其与 fresh frame 的逐字节相等由冻结 Go runner 在执行路径中强制检查；Python 审计不能独立重建未保存的临时 Reset 输出。

本报告另外直接由三份原始日志重算了 host3 的全部 576 个 cell/mode 中位数及配对比值、字节比、locality、lifecycle、有效条件和 Pareto 判定，以及两组各 576 个跨机器中位数比。结果与保存的评价和比较文件一致。远程与本地 `THREE_PLATFORM` 文件的解析后 JSON 完全一致；原始文件哈希因换行序列不同而不同。

## 注册门槛

| 门槛 | Windows i5-11300H | Linux Xeon w5-3425 | Linux 双路 Xeon Gold 5418Y |
|---|---:|---:|---:|
| H-locality：开发 / 确认通过数 | 8/8；8/8 | 8/8；8/8 | 8/8；8/8 |
| H-lifecycle：开发 / 确认通过数 | 30/48；44/48，整体失败 | 48/48；48/48，整体通过 | 48/48；48/48，整体通过 |
| 有效替代方案条件 | 0/256 | 0/256 | 0/256 |

H-locality 要求开发域 dispersed-minus-clustered 的 dictionary/ordinary 字节比中位数差至少为 0.10，确认域严格大于 0。第三台机器的开发差值范围为 0.226078–0.264796，确认范围为 0.203707–0.271513，与先前相同字节结果一致。

H-lifecycle 仅对 q∈{1,8} 注册：每个条件的 63 个 within-host 配对 Reset/fresh 总时间比取中位数，48 个开发条件均须 ≤0.90，48 个确认条件均须 <1.00。相较 Windows，22/96 个细分判定由失败变为通过，全部出现在 q=8：开发域 18 个、确认域 4 个。相较前一台 Linux，96 个判定均未变化。Windows 的失败结论继续保留。

联合工程门槛要求开发域最差 bundle 字节比 ≤0.80 且配对时间比中位数 ≤1.05；对应确认域还须字节比 <1、时间比 ≤1.05。第三台机器所有 512 个非 ordinary 的 domain-specific cell/mode 时间比均超过 1.05，范围为 1.122585–23.553872，因此开发门槛通过数为 0/256，最终有效数也为 0/256。最低值来自开发域 N=16384、q=128、member、clustered 的 dictionary；最高值来自确认域 N=4096、q=1、absent、clustered 的 fresh zlib-compact。三种 Reset 模式相对 ordinary 的最小比值仍为 1.930096。

冻结评价文件的 `effective` 数组有 288 项，其中含 32 个 ordinary 基线项。上表的 256 是排除基线后的替代方案条件数；比较器记录的 288 项判定在两组比较中均无变化。

## Reset/fresh 条件分布

每个 q 的合并范围覆盖 48 个条件（两个 domain × 两个 N × 两种 query kind × 两种 pattern × 三个 Reset 模式）。每个条件先对自己的 63 个配对比值取中位数；下表不是将所有观测混为一个估计。

| q | Reset/fresh 配对比值中位数范围 | 开发域 <1 | 确认域 <1 | 合并 ≥1 | 角色 |
|---:|---:|---:|---:|---:|---|
| 1 | 0.163432–0.395051 | 24/24 | 24/24 | 0/48 | 注册条件；开发 24/24 也满足 ≤0.90 |
| 8 | 0.567272–0.829261 | 24/24 | 24/24 | 0/48 | 注册条件；开发 24/24 也满足 ≤0.90 |
| 32 | 0.723997–1.060395 | 17/24 | 24/24 | 7/48 | 仅描述性；7 个均在开发域 |
| 128 | 0.839439–1.043863 | 16/24 | 21/24 | 11/48 | 仅描述性；开发 8 个、确认 3 个 |

这些条件中没有恰好等于 1 的比值。q=1 的对应相对时间降低范围为 60.49%–83.66%，q=8 为 17.07%–43.27%。q=32 与 q=128 的结果不能用来替换注册的小 bundle 门槛，也不能据其部分低于 1 就声称所有 bundle 都受益。

dictionary 位于 48/64 个 cell 的汇总 Pareto 前沿，恰为全部 q≥8 的 cell；q=1 为 0/16。每个 q∈{8,32,128} 均为 16/16。此处坐标是最差 bundle 字节比与 63 对时间比的中位数；这个前沿位置与 1.05 时间门槛不同，也不意味着逐请求占优。

## 两组独立环境比较

跨机器比值定义为“第三台机器 cell/mode 总时间中位数 ÷ 对照机器对应中位数”。每个中位数含该机器自己的 63 条观测。比值小于 1 表示该条件的第三台机器中位数较小；这不是跨机器逐次配对比值。

| 对照环境 | 比值 <1 | 比值 =1 | 比值 >1 | 最小值 | 最大值 |
|---|---:|---:|---:|---:|---:|
| Windows i5-11300H | 367/576 | 0 | 209/576 | 0.524184 | 2.709304 |
| Linux Xeon w5-3425 | 2/576 | 0 | 574/576 | 0.962928 | 3.199853 |

相较 Windows，最小比值来自开发域 N=4096、q=8、absent、clustered 的 reset-zlib-compact。相较 w5，最小比值来自开发域 N=4096、q=1、absent、dispersed 的 zlib-ordinary。两组最大比值均来自确认域 N=4096、q=1、member、dispersed 的 zlib-ordinary。

第三台机器最大的单条总时间为 **12.697069 ms**：确认域 N=4096、q=128、member、dispersed，batch=2、repeat=13、order=8，zlib-compact，frame 为 37,405 bytes。其 encode、decode、verify 分别为 10.498575、0.904020、1.294474 ms，恰好相加为总时间。该观测被保留；不同环境中各自最大值来自不同请求实例，不能据此作因果尾延迟比较。

## 实际环境与解释边界

第三台机器运行 Ubuntu 22.04.5 LTS、Linux 6.8.0-124-generic x86_64、glibc 2.35；控制程序使用 `/usr/bin/python3` 3.10.12。CPU 为双路 Intel Xeon Gold 5418Y，每路 24 核，共 48 物理核、96 逻辑 CPU。内存 `MemTotal=263479380 kB`，即 251.273518 GiB。Go 1.27.3、GOMAXPROCS=8，GOGC/GOMEMLIMIT/GODEBUG 均未设置；CPU 允许列表为 0-95，未进行 affinity 或 NUMA 绑定调整。

| 运行端点快照 | 测量前 | 测量后 |
|---|---|---|
| UTC 时间 | 2026-10-23 08:58:41.146896 | 2026-10-23 08:59:22.592271 |
| 1/5/15 分钟 load average | 63.79 / 66.81 / 65.01 | 64.70 / 66.54 / 64.99 |
| MemAvailable | 110823892 kB（105.689899 GiB） | 109489952 kB（104.417755 GiB） |

预检时项目所在文件系统可用空间为 420,276,285,440 bytes（391.412792 GiB）。根 cgroup 检查位置未提供 `cpu.max` 或 `memory.max`；另存的 `prior/runtime_context.json` 检查了 session、user 与父级层次，session/user 层的 `memory.max` 为 `max`，父级 `user.slice` 的 `cpu.max` 为 `max 100000`、`memory.max` 为 `max`。这些记录描述已检查的控制项，不能证明机器隔离。load average 是共享环境的上下文记录，不是本实验 CPU 利用率；端点快照不能定位某条慢观测的原因。

两台 Linux 使用同一二进制与时钟实现，但内核、CPU、双路拓扑、执行时刻和共享活动不同。本实验没有分配器、GC、调度、频率或 NUMA 的受控探针，因此不作这些机制的诊断。没有因为负载较高删除观测或另选一次更有利的运行。

三个环境各只有一次正式运行，且均为 seed 3407。本实验为单种子，存在随机噪声风险。嵌套 bundle、重复查询出现、两个 domain 和 21 次技术重复不等价于独立机器或独立 seed。结论适用于这些有效合成 fixture 及既有逐证明 verifier 流程；不等价于通用硬件排序、服务吞吐提升、网络加速、新密码学构造或加固后的不可信输入解析器。已有 compact padding-mask 异常边界保持原样。
