# Round 3 literature screening

Date: 2026-10-23. Scope: proof representation and compression selection. This is a targeted search, not an exhaustive systematic review. Dedicated literature MCP tools were unavailable; primary publisher/author/project pages were used. No claim of a newly discovered research gap is made.

| Source / status | Mechanism and function | Reported outcome / applicable setting | Implication |
|---|---|---|---|
| Jellyfish Merkle Tree (2021), official full paper inspected in earlier review and rechecked: https://developers.diem.com/papers/jellyfish-merkle-tree/2021-01-14.pdf | Compacted tree nodes, versioned storage and shorter proofs | Addresses storage, I/O and computation in a Diem authenticated state tree; no numerical speedup imported into our study | Empty-path omission and efficient proof formats are established |
| Celestia SMT, fixed commit dba215ccb88452c31d823bf156d8f35406c1dc04, proofs.go and tree code to be archived and inspected | Variable-depth sparse proofs; CompactProof removes placeholder siblings using a bitmask; DecompactProof restores them | Production-project source, not a peer-reviewed performance claim; no speedup promised | Suitable independent implementation for native-versus-compact comparison; different leaf/default conventions from Round2 |
| Nervos SMT official README/source: https://github.com/nervosnetwork/sparse-merkle-tree | Compacted tree, multi-leaf inclusion/non-inclusion proofs | README documents features and complexity; not reproduced here | Confirms mature compact proofs exist; not a drop-in codec for sequential intermediate roots |
| Hugo De la cruz / Ipsilon, Code Merkleization Practical Implementation & Analysis, full author report: https://notes.ethereum.org/@ipsilon/code-merkleization-implementation-analysis | Baseline and slim proofs, zero-node omission, RLP and Snappy baseline compression | Report analyzes 1,016,695 blocks; mean proof sizes 405,677 / 279,160 / 159,031 bytes for baseline / slim / Snappy baseline. | Datacomp: Locally Independent Adaptive Compression (ICDCS 2016), author PDF search record: https://lasr.cs.ucla.edu/reiher/papers/icdcs_2016.pdf | Adaptive compression according to runtime communication conditions | Author PDF fetch timed out; only title/search extract verified, no numerical claims used | Generic adaptive compression selection is prior art; further full-text review needed before a selector novelty claim |

Searches included sparse Merkle proof binary/bitmap compression benchmarks and adaptive lossless compression cost models. Neural-network compression results were excluded as different tasks. Newer unverified secondary pages were not used to establish novelty.

Conclusion: first measure whether the claimed advantage survives a binary baseline and native external proof representation. Only then consider a predictive study. The experiment below is an explicitly limited screening study; neither an adaptive algorithm nor network/concurrency improvements have yet been established.
