# Preregistration: same-task proof representation conditions

Date: 2026-10-23. Literature and placement decisions precede this plan in LITERATURE.md and ADAPTATION.md. This is a new study, not a threshold change or a rerun of a previous gate. The final source/config hash registration must be created before any formal timing. Functional tests and unmeasured fixture checks may precede registration.

## Research questions and gates

RQ1: Does controlled path locality materially change the relative bytes of a node dictionary compared with full ordinary binary bundles? For each domain, N, kind and q in {32,128}, compare the median of three dictionary/ordinary byte ratios for clustered and dispersed queries. H-locality requires the clustered ratio to be at least 0.10 lower (ten percentage points) in EVERY development comparison, and the same direction (strictly lower) in EVERY confirmation comparison. Exact size identities and restored proofs must all pass. This is a synthetic workload effect, not proof of production prevalence or an isolated latency mechanism.

RQ2: Does fresh compressor construction explain a material part of local processing cost? For each zlib representation (ordinary, compact, dictionary), N, kind, pattern and q in {1,8}, H-lifecycle requires the median paired reset/fresh total-time ratio <=0.90 in EVERY development cell and <1.00 in EVERY confirmation cell. Fresh and reset frames must be byte-identical on the pinned toolchain. q=32,128 are prespecified descriptive extensions. Reset reuses allocation but clears history; it is not a persistent compression stream.

RQ3: Which measured conditions offer smaller bytes without a material median local-wall-time penalty? Classify EACH mode/cell against ordinary using worst-of-three byte ratio <=0.80 and median of 63 paired total ratios <=1.05. Classifications are descriptive engineering gates, not significance tests. Match domains by (N,kind,pattern,q,mode). An effective cell must pass development and have worst-of-three byte ratio <1.00 and median total ratio <=1.05 on confirmation. The 20% byte threshold is a development threshold; confirmation checks direction, not the same magnitude. H-locality and H-lifecycle likewise test a material development threshold followed by directional confirmation. Do not require any mode to win all cells. Report failures, per-stage and tail measurements, and complete Pareto comparisons among all modes.

No method novelty, crypto-security improvement, library ranking, runtime generalization or measured network speedup is hypothesized. No SOTA multiproof claim. If all meaningful distinctions fail, retain the null result and do not claim that additional rows alone improved publication quality.

## Frozen experiment matrix

- seed=3407, only seed. Domains `r4/dev/3407` and `r4/confirm/3407`; generated before examining formal measurements and never retuned. Both domains run as planned, irrespective of development outcome. Confirmation is not used for selection or modification.
- pinned Celestia SMT dba215ccb88452c31d823bf156d8f35406c1dc04; SHA256; unchanged update/prove/compact/decompact/verify; Go1.27.3 Windows amd64.
- N={4096,16384}; deterministic keys SHA256("r4/{domain}/3407/key/{i}"), values SHA256("r4/{domain}/3407/value/{i}"). Absent candidates from separate `absent/{i}` strings and verified absent. Persist all tree keys/values/root as replay checkpoints.
- q={1,8,32,128}; member and absent bundles separately; dispersed and clustered patterns; 3 bundles per cell. Every bundle has q distinct keys and preserves query order. Cross-q and cross-bundle reuse is permitted and recorded; these are not independent biological/statistical samples.
- Each batch b uses fixed path-prefix nibble {0,5,10}[b]. Clustered candidates satisfy upper4bits(SHA256(key))=prefix. Dispersed candidates use a deterministic pseudorandom permutation with no replacement within the bundle. Choose q-prefixes of each ordered candidate list, yielding nested q conditions. Do not reject/select trees using timing or size. Insufficient candidates is a correctness/design failure, not an opportunity to tune a prefix. Candidate generation cap for absent keys is 65536 per tree. q=1 is a negative control for cross-query sharing; do not interpret a locality effect at q=1.
- Nine timed modes: ordinary, compact, dictionary, zlib-ordinary, zlib-compact, zlib-dictionary, reset-zlib-ordinary, reset-zlib-compact, reset-zlib-dictionary. Old four modes use unchanged codec functions. New API default remains ordinary. Zlib always covers the entire bundle at level6, with no external dictionary. Reset modes retain a writer per representation, reset before EVERY frame and create a fresh decoder exactly as the fresh modes do. Buffers allocated identically to fresh modes; do not additionally reuse buffers/readers.
- Total: 64 domain-specific cells, 192 bundles, 9 modes, 21 repetitions = 36,288 timed observations. Three reset modes have the same frame bytes as their fresh counterparts; they are not three new formats. Two warmups per mode per bundle. One pseudorandom generator seeded 3407 shuffles bundle execution order, then its subsequent draws permute mode order within each paired repetition. Paired observations share bundle and repeat index.

## Timing and diagnostics

One sequential process; default Go GC/GOMAXPROCS as detected and recorded. No affinity/power changes. QPC with frequency recorded; clock regression test must pass before launch. Timed path: encode -> decode -> ordinary verification of all queries. Include counter overhead. No subtraction, outlier removal, early stopping for poor performance, concurrent local testing/compilation/analysis during formal timing, or per-mode tuning. Preparation/proof generation, reference-frame correctness checks and writes are excluded. Keep outputs live through final timestamp.

Record per observation: domain,N,q,kind,pattern,batch,repeat,order,mode,wire bytes,encode/decode/verify/total ns. Check total is positive and equals stage sum. Record median,p95,max per mode/cell and counts of slower and >1.05 pairs. Ratios use matched observations; no independent-sample confidence interval over technical repeats. Keep every slow sample. Descriptive Pareto coordinates for each domain-specific cell are (worst-of-three mode/ordinary byte ratio, median-of-63 paired mode/ordinary total-time ratio). A mode is dominated when another has both coordinates no greater and at least one strictly smaller. This is a summary comparison, not per-request dominance; do not mix the Pareto rule with the 1.05 engineering tolerance.

Per bundle: all query objects and six unique frames, actual native depths, retained/default counts, S(total side-node occurrences), U(unique node byte values), prefix/unique-query checks, compact/dictionary byte-identity residuals. Report occupancy and actual structure, not just N. Dictionary size identity: delta=30*S-32*U-2. Compact delta=sum(32*(d-k)-2-ceil(d/8)). Duplicate nodes include zero placeholders, explicitly counted.

## Prespecified optional engineering calculation (not a network experiment)

For each bundle and mode, report the sequential non-overlapped payload model L(B)=t_local+8*W/B, where B is effective application-payload bit/s, not physical-link rate. Compute delta_t as the median of 21 paired (mode total - ordinary total) differences in seconds, and delta_W as ordinary bytes minus mode bytes for that same bundle. When delta_W>0 and delta_t>0, B*=8*delta_W/delta_t is a modeled break-even: B<B* favors the smaller frame. Report all quadrants and equality cases rather than forcing a finite threshold. A smaller/equal frame with nonpositive delta_t is model-favorable for all B (strictness depends on ties); a larger frame with lower time reverses the bandwidth inequality. Larger/equal bytes and nonnegative delta_t offer no strict improvement. Include p10/p90 paired time differences to expose unstable denominators. Do not average bytes from one bundle with time from another. This calculation has no gate, no fitted coefficients and no effect on selection. It omits RTT, protocol headers, queuing, overlap and actual sockets; it is not evidence of network acceleration.
